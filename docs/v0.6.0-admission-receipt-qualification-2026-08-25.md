## Receipt contract

`gpuq.admission-receipt.v1` is derived by the broker from the accepted `JobSpec`
and live allocation. It contains no environment values and binds:

- canonical launch-spec SHA-256;
- argv SHA-256 and argument count;
- explicit environment-override SHA-256 and sorted keys;
- cwd, owner, label, mode, GPU count, estimates, and timeouts through the launch
  spec;
- resolved executable path and executable file SHA-256;
- broker version/instance and submit/start timestamps;
- allocated physical GPU IDs;
- SHA-256 of the complete effective child environment after the broker injects
  `CUDA_VISIBLE_DEVICES`;
- canonical receipt SHA-256.

The broker persists the receipt as mode-0600 `admission.json`, streams it in the
started event, optionally writes it through `gpu-run --receipt-out`, and serves
the same value through `gpuq receipt <job-id>` only while the job is active.

The executable is resolved and hashed at admission, then resolved and hashed
again immediately before spawn. The broker executes the resolved path. Path or
content drift fails before the command starts and releases the allocation.

## Additional hardening discovered during implementation

Receipt fingerprinting made two lifecycle races reproducible and they were
fixed in the same implementation commit:

1. cancellation during `create_subprocess_exec` could occur after fork but
   before the `Process` handle was assigned; spawn is now shielded until the
   handle can be terminated and reaped;
2. Python 3.9 could leave the scheduler shutdown gather pending while cancelling
   an `Event.wait` nested in `wait_for`; the scheduler now owns and explicitly
   reaps wake/poll tasks.

Both regressions have focused tests and the exact host suites completed without
leftover child processes or sockets.

## Remaining boundary

The receipt hashes the admitted executable but does not recursively hash every
dataset, model, image, config, or compatibility file named by its argv. Those
remain task/evaluator-owned artifacts. The effective-environment digest is
opaque evidence of the broker's child environment; independent controllers can
recompute the explicit-override digest but should not expect access to inherited
secret values.
